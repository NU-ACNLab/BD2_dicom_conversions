# BD2 DICOM conversion — merged UCB / UCL / SUT pipeline

One copy of the pipeline that used to live in three branches. Every script now
takes the site as its first argument.

```bash
# what is in dicoms/uncompressed, and which site/participant each folder is
python scripts/0_identify_dicoms.py

# every subject without a defaced T1w yet -- site auto-detected per folder
bash scripts/5_wholedir.sh ses-1              # add UCB|UCL|SUT to filter

# one subject
bash scripts/4_single_sub.sh SITE SUB SES [--src DIR]
```

Individual stages:

```bash
python scripts/0_identify_dicoms.py       [--tsv PATH] [--participants]
bash   scripts/1_dic_to_nifti.sh          SITE SUB SES [--src DIR]
python scripts/2_nifti_to_bids_naming.py  SITE SUB SES [--dry-run]
python scripts/2b_phase_to_radians.py          SUB SES [--dry-run]
bash   scripts/3_deface.sh                SITE SUB SES
python scripts/6_qc_qsm.py                     SES [SUB ...] [--tsv PATH]
python scripts/7_qc_images.py                  SES [SUB ...] [--outdir DIR]
```

Steps 1–3 take the site; 0, 2b and the QC steps do not, because nothing about
them is site-specific. `4_single_sub.sh` runs all of them in order.

## Folder names are not subject labels

Sites export DICOM folders under whatever name they like, and the names are
neither consistent nor always correct — the folder `1-845` holds UCL
participant `P00<nnnn>`. The headers are consistent, so
`0_identify_dicoms.py` reads site and participant from the data and reports
where the folder name disagrees. It is read-only: it renames nothing.

| DICOM tag | Use |
|---|---|
| `InstitutionName` | Site. `UC Berkeley` → UCB, `University College` → UCL, `Swinburne University` → SUT |
| `DeviceSerialNumber` | Independent cross-check on site (166319 / 166108 / 167089). A conflict is reported, not resolved |
| `PatientID` | Participant number for **UCB** (`Johnson_Berk_RandR_<n>` → `rb860`) |
| `PatientName` | Participant number for **SUT** (`2514xRNR_<n>` → `rs1253`) |
| `StudyInstanceUID` | Detects the same scan sitting in two folders |

**SUT is the trap.** Its `PatientID` is a scanner-local number (`<6-digit local id>`) with
no relation to the study ID; only `PatientName` carries it. Reading `PatientID`
uniformly across sites produces silently wrong labels for every SUT subject.

Labels are `r` + a site letter: `rb` Berkeley, `rl` London, `rs` Swinburne.
`5_wholedir.sh` maps folder → label automatically and passes the source
directory through with `--src`, so a folder need not be named after its label.

### UCL: the study number is only in the folder name

UCL scans carry **no study participant number anywhere in the header**.
`PatientID` is UCL's own sequential scan accession (`P00<nnnn>`, `P00<nnnn>`, …),
`PatientName` is a deidentified date-time stamp, and searching every element of
every series for the known study numbers finds nothing. Deriving a label from
the P-number yields a plausible but wrong subject ID, which is worse than none.

So for UCL the **folder name is the record**, and these spellings are accepted:

| Folder | Label |
|---|---|
| `rl845`, `RL845` | `rl845` |
| `1-845` | `rl845` |
| `845` | `rl845` |
| `P00<nnnn>` | *unidentified* — reported as `NEEDS RENAME` |

Rename a UCL folder to its study number and the label follows. Until then the
subject is reported unidentified and `5_wholedir.sh` skips it rather than
converting it under a guessed ID.

There are two ways to convert a UCL subject:

```bash
# 1. give the label and the path explicitly -- no renaming needed
bash scripts/4_single_sub.sh UCL rl169 ses-1 \
     --src "$PWD/dicoms/uncompressed/P00<nnnn>"

# 2. rename the folder once, then batch mode finds it
mv dicoms/uncompressed/P00<nnnn> dicoms/uncompressed/rl169
bash scripts/5_wholedir.sh ses-1 UCL
```

Both produce identical output. Renaming is worth doing if you want the batch
runner to handle UCL unattended, and it also lets `participants.tsv` record the
`source_id`, `scanner`, `software_version` and `study_date` for that subject —
those columns read `n/a` for a subject converted from an unrenamed folder,
because nothing then links `bids/sub-rl169` back to its DICOMs.

## One dataset, three sites

`bids/` is a single BIDS dataset. Subject labels already encode the site
unambiguously, so the sites do not need separate trees, and BIDS Apps and QSM
pipelines run once over the whole cohort.

Site membership lives in `bids/participants.tsv`, regenerated by
`scripts/0_identify_dicoms.py --participants` (and automatically at the end of
`5_wholedir.sh`). It lists only subjects actually present in `bids/`, and
carries `source_id` — the site's own identifier — so every label stays
traceable back to their records.

`--dry-run` prints every rename without touching the disk. Worth using the
first time you run a site.

The project root defaults to the original hardcoded path and can be overridden:

```bash
export BD2_ROOT=/path/to/BD2_dicom_conversions
```

## Where the site differences live

All naming differences are in the `SITES` table at the top of
`2_nifti_to_bids_naming.py`. Each entry is an ordered list of rules:

- `("one", glob, bids_suffix)` — rename every match to that suffix
- `("t1w", glob, None)` — T1w; first match becomes `run-1`, second `run-2`, …

Order matters, because a file renamed by an earlier rule is invisible to later
ones. To add a fourth site, add a list to `SITES` and a case to the `CLEANUP`
switch in `3_deface.sh`. Nothing else is site-aware.

Cleanup patterns (`3_deface.sh`): UCB removed localizers, SUT removed
localizers and MPR reconstructions, UCL swept anything still prefixed with the
raw subject ID.

## Changes from the three branches

**Fixed — extension parsing.** The branches pulled the file extension with
`file.split(".", 1)[1]` in some sections and `file.split(".", 2)[2]` in others.
`split(".", 2)` only works if the filename contains exactly one period before
the extension; `split(".", 1)` only works if it contains none. UCB and UCL used
both depths in the same file, so one set of sections was always wrong: with a
period-free `PatientName` they raise `IndexError` at the T1w block and abort
before DTI/QSM/RL ever run; with a single period they instead write names like
`sub-001_ses-1_run-1_dir-AP_dwi.UCB001--DTI_AP--s12--e1.nii.gz`. SUT used depth
1 consistently and was correct. Replaced with `get_ext()`, which matches a
known suffix (`.nii.gz`, `.nii`, `.json`, `.bval`, `.bvec`) and is unaffected by
periods anywhere in the path.

**Fixed — SUT T1w defacing.** SUT only defaced `run-1`, so a second T1w shipped
with the face intact. `3_deface.sh` now defaces every `*_T1w.nii.gz` in `anat/`,
and warns instead of silently continuing if pydeface produces no output.

**Fixed — T1w run numbering.** The branches assigned run numbers from raw
`glob.glob` order, which is filesystem order, so which acquisition became
`run-1` was arbitrary; a third T1w would have been renamed `run-2` on top of the
second. Now sorted, and numbered `run-1`, `run-2`, `run-3`, …

**Fixed — UCB double slash** in the `5_wholedir.sh` skip check.

**Carried over as-is — UCL's RL fieldmap directions.** UCB and SUT map the
reverse-direction RL fieldmap to `dir-PA`; UCL maps it to `dir-AP`, the
opposite, while UCL's *MID* fieldmaps still follow the UCB/SUT convention. This
is preserved and flagged in a comment in `SITES["UCL"]`. **Check it against
`PhaseEncodingDirection` in the JSON sidecars before running UCL** — if UCL was
wrong, swap the two suffixes there. Getting this backwards inverts distortion
correction.

**Fixed — QSM naming and location.** All three branches named the QSM echoes
`task-echo_flip-16_echo-N_part-{mag,phase}_bold` and swept them into `fmap/`.
They are not BOLD runs of a task, and `fmap/` is not where they belong. They are
now `echo-N_part-{mag,phase}_MEGRE` in `anat/` — MEGRE being the BIDS suffix for
multi-echo gradient echo, which is what QSM source data is. The `*MEGRE*` rule in
`3_deface.sh` must stay ahead of the `*phase*` and `*mag*` rules, or those would
still pull the echoes into `fmap/`.

**Fixed — one unusable series aborted the whole subject.** `1_dic_to_nifti.sh`
ran `dcm2niix` per series with no error handling, so the loop's exit code was
whatever the *last* series returned. Berkeley exports a `PhoenixZIPReport`
series — a Siemens protocol dump, modality `SR`, containing no images — and
dcm2niix exits 2 on it. Because it is numbered `99` it sorts last, so every
Berkeley subject ended step 1 with a non-zero exit, `4_single_sub.sh` hit its
`|| exit 1`, and steps 2–7 never ran: the subject was left as raw dcm2niix
output, unrenamed and unsorted. UCB is the only affected site; UCL and SUT have
no such series. Each series is now converted independently, a failure is
reported and skipped, and only a subject that produced no NIfTI at all fails.

**Fixed — `5_wholedir.sh` skip check.** It tested for `anat/`, which
`2_nifti_to_bids_naming.py` creates before doing any work, so a subject that died
mid-pipeline was skipped by every later run and stayed half-converted. Now tests
for `anat/*_T1w.nii.gz` — a marker only a successful run leaves.

**Fixed — stale `BD2_ROOT` default in `3_deface.sh`.** It pointed at a different
machine's home directory. With `BD2_ROOT` unset, `$BASE` resolved to a
nonexistent path, so every `mv` failed silently (each ends in `2>/dev/null`),
pydeface found no T1w, and the script exited 0 having done nothing.

## QSM / MEGRE quality control

### Phase must be in radians

dcm2niix writes Siemens phase in raw 12-bit scanner units (`-4096..4095`), not
radians. Every QSM pipeline — QSMxT, SEPIA, TGV-QSM, MEDI — expects `-pi..+pi`.
Handed scanner units they do **not** error: they unwrap "successfully" and
produce a susceptibility map wrong by a factor of ~1300.

`2b_phase_to_radians.py` converts in place, stamps `"Units": "rad"` in the
sidecar, and is idempotent. It runs automatically as part of `4_single_sub.sh`.
Some pipelines (QSMxT ≥ 6) auto-detect and rescale — check yours before
double-scaling.

### Automated checks — `6_qc_qsm.py`

Prints PASS/WARN/FAIL per subject and exits 1 on any FAIL, so it can gate a
batch. `--tsv PATH` also writes a table. Checks inventory (8 mag + 8 phase,
paired), echo times (present, monotonic, mag/phase agree, uniform spacing),
geometry (shape and affine identical across echoes), phase units, and
magnitude decay across the echo train.

Two WARNs are expected for this protocol and are not conversion faults:
non-uniform echo spacing (dTE drifts 4.82 → 4.04 ms — use a pipeline that reads
per-echo TEs), and a 139 mm z-extent, which is a slab rather than a whole head.

### Visual checks — `7_qc_images.py`

Writes four PNGs per subject to `derivatives/qc/sub-X/SES/`, plus a
cross-subject phase contact sheet at the top of `derivatives/qc/`. These catch
what no automated metric can:

- **`mag-echo1.png`** — anatomy and gross quality. Ghosting replicated along the
  phase-encode axis means motion, and QSM is unforgiving of it.
- **`mag-echoN.png`** — is there still signal at the longest TE? Check dropout
  near sinuses and ear canals.
- **`phase-echoN.png`** — *the highest-yield single image.* Look for **open-ended
  fringe lines**: a black/white wrap boundary that starts inside the brain and
  stops mid-parenchyma instead of running out to the brain edge. That is a phase
  singularity from failed coil combination; every unwrapping algorithm fails
  around it and the resulting chi map looks plausible with a garbage region
  inside. Also check wrap density (fringes too dense to count means the TE range
  is too long for the field inhomogeneity present) and graininess inside tissue,
  which means low SNR at that echo.
- **`coverage.png`** — sagittal and coronal; confirm the slab covers your ROIs
  before processing a whole cohort.

The phase montage uses the **last** echo deliberately. Phase accrues with TE, so
a broken echo train still looks fine at 3 ms.

### After the pipeline

QC the outputs too: brain mask (covers the slab, does not leak into skull),
unwrapped field map (no residual wraps), and the chi map itself. Sanity-check
values — globus pallidus ≈ **+0.10 to +0.20 ppm**, red nucleus and substantia
nigra positive, white matter ≈ −0.02 to −0.05 ppm, CSF ≈ 0. If deep grey nuclei
are not clearly positive, suspect the phase units before suspecting biology.
This is the backstop that catches a missed rescale.

## Task events — `8_behavioral_to_events.py`

Turns the PsychoPy in-scanner output under `behavioral/` into BIDS
`events.tsv` for MID and RL.

```bash
python scripts/8_behavioral_to_events.py                # everyone
python scripts/8_behavioral_to_events.py rs1356 rb1217  # just these
python scripts/8_behavioral_to_events.py --dry-run      # report only
```

Files land in `bids/sub-XX/ses-1/func/` for subjects that have been converted,
and in `behavioral/events_pending/` for the ones that have not — there are
more behavioral subjects than scans, and events without a bold file would fail
validation. Move them across after conversion. Every run, written or not, is
logged to `behavioral/events_qc.csv`; the script exits 1 if anything was
skipped.

Three columns, `onset duration trial_type`. Durations are measured from the
logged onsets, not the nominal values, because the MID target duration is
staircased per trial and the anticipation window jitters.

| Task | Runs | `trial_type` |
|---|---|---|
| `mid` | csv `run` 1, 2 → `run-01`, `run-02` | `ant_<cond>`, `motor_period`, `motor_response` (0 s, hits only), `rew_<cond>_Hit\|Miss` |
| `RL` | csv `runs.thisN` 0–2 → `run-01`–`run-03` | `decision`, `select_optimal\|nonoptimal`, `outcome_reward\|noreward`, plus `_noresp` variants |

`<cond>` is `{reward,loss}.{high,low,neut}`. Fixations are left as implicit
baseline. Hit/Miss comes from whether an RT was logged — `Tgt.ACC` splits
misses across both 0 and 3, `Tgt.ACCfeedback` agrees with the RT on every
trial in the dataset.

### Three things this script does not guess

**MID run 0 is not a scanned run.** It is the MRT calibration block: no cue,
no bold. Only runs 1 and 2 become events files.

**Onsets are already run-relative.** Every run's clock restarts at its own
trigger (MID puts its first cue at ~5.0 s, RL at ~0.001 s), so nothing is
re-referenced. Do not subtract a first-fixation onset the way the eprime-era
scripts had to.

**Response keys differ by site**, and changed within UCL mid-study — `1/2`,
`0/1`, `6/7`, `2/3` and `b/y` all appear. The left/right mapping is recovered
per run from the data instead of hardcoded: reward only ever follows a choice
of `good_side`, so among rewarded trials each key appears with exactly one
side. A run that does not pin the mapping down is skipped, not guessed.

Restarts and aborts are likewise never resolved automatically. A run is
written only when exactly one file holds a complete copy of it; when several
do, the QC table names them all and leaves the choice to you.

## Verification

`2_nifti_to_bids_naming.py` was run against synthetic dcm2niix trees for all
three sites and diffed against each original branch script. SUT is byte-identical.
UCB and UCL differ only where the originals crashed or produced malformed
extensions, as described above.
